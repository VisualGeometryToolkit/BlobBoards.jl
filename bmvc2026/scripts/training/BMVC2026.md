# BMVC 2026 training run

End-to-end recipe for the BMVC 2026 descriptor training experiment: annotate
all calibrated and uncalibrated sources under `blobboard_training/`, split by
board UID, train the descriptor on the current B200 config.

## TL;DR

Single SLURM submission that chains everything (annotate → split → train):

```bash
cd BlobBoards.jl      # on the cluster's login node
BB_DATA=/path/to/blobboard_training BB_OUT=/local/disk/bmvc2026 \
BB_PROJECT=/path/to/bb-slurm-env \
    bash bmvc2026/scripts/training/slurm/submit_bmvc2026.sh
```

Three jobs land in the queue with `afterok` dependencies. Monitor:

```bash
squeue -u $USER
tail -f bb-*.log
```

## Outputs

Every run lands under a timestamped dir at `$BB_OUT`:

```
$BB_OUT/
  _sources.txt           — flat (source|camera) manifest (input to driver_scm)
  truth_images/          — per-frame .jld2 annotations + refs/<uid>.jld2 + _log.jsonl
  splits/                — train.jld2, val.jld2, test.jld2 (split by board UID, no leakage)
  bmvc2026/data/exp_pro/models/           — best_model.jld2, TensorBoard event files
```

`BB_OUT` is required; the run lands in `$BB_OUT/<timestamp>/`. **Must be on
local disk** — SMB mounts hang JLD2 writes under concurrent load.

## Phases

### 1. Annotate

`submit_bmvc2026.sh` builds a sources file (one calibrated/uncalibrated
group per source dir), then submits `sbatch_scm.sh` which spawns
`driver_scm.jl` distributed across `N_WORKERS+1` tasks. Each task gets
one GPU via `--gpus-per-task=1`.

Per-image kwargs come from `FindBoardsConfig(geometry =
HomographyGeometry(min_inliers=10))` — the `build_annotations` defaults;
nothing BMVC-specific.

### 2. Split

`sbatch_split.sh` (depends on annotate via `afterok`) runs
`split_training_data` on a high-memory node (`--mem=512G`). The
loader concatenates all per-frame patches + confusers into one tensor
(~240 GB on this corpus), which is why we don't try this on a 128 GB host.

Output: `splits/{train,val,test}.jld2`, split by board UID, no leakage.
Defaults: 80% train / 10% val / 10% test (by patch count, greedy).

### 3. Train

`sbatch_train.sh` (depends on split via `afterok`) runs
`train_bmvc2026.jl` with `BB_TRAIN_PATH`, `BB_VAL_PATH`,
`BB_OUTPUT_DIR` from env. Single B200, 24 h walltime.

Config (B200, 180 GB HBM3e, ~30 GB working set):

```
blobs_per_batch     = 384
views_per_blob      = 10
confusers_per_batch = 2048
batches_per_epoch   = 0   # auto = ceil(n_labels / blobs_per_batch)
patch_size          = 64
```

On A100 (40 GB) drop to `96 / 10 / 512` and rescale AdamW LR by ½ (sqrt rule
on a 4× smaller batch).

## Tunable env vars (override at submit time)

| Var | Default | Notes |
|---|---|---|
| `BB_DATA` | required | Dataset root. Must contain `{boards,images,videos,models}/`. |
| `BB_OUT` | required | Run root; a timestamped subdirectory is created. Local disk only. |
| `BB_PROJECT` | required | Julia project — registered deps only, no `Pkg.develop` (see `slurm/README.md`). |
| `N_WORKERS` | `2` | GPU workers for annotation. Driver gets +1 task w/ 1 GPU. |
| `CPUS_PER_TASK` | `28` | 1/8 of an 8-GPU, 224-cpu node. Lower if other tenants are holding CPUs. |
| `BB_N_FRAMES` | `30` | Frames per video (stride decimated). |

## Local debug path (single GPU, single process)

Skip SLURM. Use the env vars from `train_bmvc2026.jl`:

```julia
ENV["BB_TRAIN_PATH"] = "<…>/splits/train.jld2"
ENV["BB_VAL_PATH"]   = "<…>/splits/val.jld2"
ENV["BB_OUTPUT_DIR"] = "<…>/checkpoints"
include("examples/training/train_bmvc2026.jl")
```

For local annotation use `examples/training/build_annotations.jl` directly —
it now auto-discovers `data_dir()/blobboard_training/{images,videos}/`
and supports `ENV["RESUME_DIR"]` to continue an aborted run. CUDA backend
required (CPU adapt doesn't support EllipticFrame detections).

## Evaluating a trained checkpoint

```julia
using BlobBoards
descriptor_network = DescriptorNetwork("<…>/bmvc2026/data/exp_pro/models/best_model.jld2")
# Feed into examples/pipeline/find_boards.jl as the gallery descriptor.
```

The training extension writes `best_model.jld2` whenever val FPR@95
improves. TensorBoard logs land alongside.

## Troubleshooting

- **OOM in the adaptation kernels (`_adapt_ka`)**: large-detection images
  (e.g. iPhone with ~32k blobs) hit `(Σ(2hw+1)² × 6 × Float64)` ≈ 22 GiB.
  Cap via `FindBoardsConfig(max_detections = 8000)` (the response-rank cap,
  applied per polarity subset).
- **Cascade failures after one bad image**: `build_annotations` now
  wraps each source in try/catch with GC+reclaim between sources, so a
  single failing image no longer kills the run (BB 0.4.1+).
- **Resume an aborted local run**: `ENV["RESUME_DIR"] = "<path>"; include(…)`.
  Per-source `_log.jsonl` markers cause already-done sources to skip.
