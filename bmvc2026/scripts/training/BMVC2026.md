# BMVC 2026 descriptor training run

The descriptor training experiment as two stages of the paper's stage graph
(`configs/reproduce.toml`): `annotations` (annotate every source of the
training footage, split by board UID) and `train_descriptor` (train on that
corpus). Each reads ONE config of record; the corpus is written as data of its
own tier (`bb_descriptor_annotations`, Eval's `keyed_data_dir`), the descriptor
into its keyed run directory under results_root(); see README.md beside this file.

```bash
bash bmvc2026/scripts/reproduce/reproduce_results_dgx.sh --only=annotations
bash bmvc2026/scripts/reproduce/reproduce_results_dgx.sh --only=train_descriptor --no-deps
```

## Inputs

`configs/training/annotations.toml` `[inputs.<id>]`: the boards
(`blobboard_training/boards`), the photo sets (`blobboard_training/images/<dir>/`,
a sibling `<dir>.json` = its camera, else uncalibrated) and video sets
(`blobboard_training/videos/<dir>/`), and the descriptor network that finds
the boards (bb_assets). Calibrated sources use PoseGeometry(camera),
uncalibrated ones the homography path.

## Outputs

```
<data_root()/bb_descriptor_annotations/annotations-<key>>/truth_images/   per-frame .jld2 annotations + refs/<uid>.jld2 + _log.jsonl
<…same>/splits/         train.jld2, val.jld2, test.jld2 (by board UID, no leakage)
<descriptor run>/                 best_model.jld2, TensorBoard event files
```

The same config is the same directory: an aborted annotation resumes there
(per-source `_log.jsonl` markers); a changed value is a new run. The corpus is
~240 GB once concatenated by the split: run it on a high-memory node.

## Training config

`configs/training/train_descriptor.toml` `[train]` states every
`TrainingConfig` field (B200: 384 blobs × 10 views + 2048 confusers = 5888
patches per step, ~30 GB). On an A100 (40 GB) drop to 96 / 10 / 512 and halve
the AdamW learning rate (sqrt rule) — in a config of its own, which is then a
run of its own.

## Troubleshooting

- **OOM in the adaptation kernels (`_adapt_ka`)**: large-detection images
  (e.g. iPhone with ~32k blobs) hit `(Σ(2hw+1)² × 6 × Float64)` ≈ 22 GiB.
  Cap via `FindBoardsConfig(max_detections = 8000)`.
- **Cascade failures after one bad image**: `build_annotations` wraps each
  source in try/catch with GC+reclaim between sources.
